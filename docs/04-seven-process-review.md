# docs/04 · 对抗性审查案例（脱敏版 L1）

> 本页是方法论验证案例的**结论摘要**。审查引擎构成、身份分工、全量推演记录属 🔒 协作层。

## 案例背景

对一个「GitHub 优化 + Fork 独立化 + 突破路线图」的 AI 生成方案，执行七维对抗性审查：主张 → 证据 → 攻击 → 防御 → 反例 → 综合 → 补丁。

## 三项审查结论

| 原主张 | 关键攻击 | 修正 | 评分 |
|--------|---------|------|------|
| 主页品牌化 | 低活跃账号挂统计卡 = 自曝短板；美化被排在治理之前 | 先治理后美化，统计卡设活跃门槛 | 8/10 |
| Fork 必须切断+重写历史 | GPL 衍生闭源违约；重写丢溯源；保 Fork 提 PR 被严重低估 | 合规三检前置 + 双路线决策树 | 6.5/10 |
| 突破方向含工时/收益数字 | 数字无基准数据；方案遗漏 Agent 互联协议 | 数字降级为待验证假设，方向增补 | 7/10 |

## 决策规则（可复用的部分）

- 综合评分 ≥ 7 → 内容可用，但 **PATCH 项必须全部落实后才执行**
- 不可验证的数字承诺一律显式标注，禁止以结论形式对外陈述
- 发表前必做资产分型：**怕被抄的知识 → 藏配方分层发布**（本仓库即此规则的实例）
