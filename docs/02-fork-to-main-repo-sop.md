# docs/02 · Fork → 独立主仓迁移（脱敏版 L1）

> **完整可执行 SOP（含命令级操作）属 🔒 协作层**，本页仅公开决策框架与合规红线。

## 核心结论

**License 决定一切。** 先过合规三检，再谈切断不切断——顺序错了是法律风险，不只是美观问题。

## 合规红线速查

| 协议 | 衍生代码开源义务 | 署名义务 |
|------|-----------------|---------|
| GPL 系列 | ✅ 强制（传染性） | ✅ 强制 |
| MIT / Apache-2.0 | ❌ 不强制 | ✅ 强制 |

⚠️ **红线案例**：GPL 衍生项目改名换 Logo 后闭源 = 违约，可被下架追责。

## 路线决策框架

```
原项目活跃吗？
├─ 活跃且想借流量 → 路线甲：保留 Fork + 高质量上游 PR（声望积累最快）
└─ 不活跃 / 方向分歧 / 需要独立品牌 → 先过合规三检 → 路线乙：独立主仓
```

**对攻实证**：「必须切断 Fork」是被夸大的默认项——路线甲的成本收益比常被严重低估。

## 差异化重塑三件套

1. 独立代号 + 一句话差异化
2. 自绘架构图（突出你改的模块）
3. 能力对比表（原项目 vs 本项目）
